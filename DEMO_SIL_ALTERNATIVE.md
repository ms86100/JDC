# JDC Script Engine — Live Demo Guide

## Prerequisites

Start the required services:
```bash
docker compose up -d postgres redis auth-service
docker compose up -d issue-service comment-service project-service user-service search-service
docker compose up -d workflow-service gateway
```

Wait for all services to be healthy:
```bash
docker compose ps
```

The Script Console UI is at: **http://localhost:8080/workflows/admin/scripts**

## Demo Scenario 1: DSL Transpiler + Issue Manipulation

**What it proves:** The DSL transpiler converts SIL-like syntax into JavaScript, then the script engine creates real issues, adds comments, searches via JQL, and manages labels — all in one execution.

### Step 1: Open the Script Console

Navigate to **http://localhost:8080/workflows/admin/scripts** and click the **Console** tab.

### Step 2: Paste this script into the editor

```javascript
// ============================================================
// DEMO 1: JDC Script Engine — Real Data Manipulation
// This script creates an issue, adds a comment, searches via
// JQL, manages labels, and demonstrates the testing framework.
// ============================================================

console.log("=== JDC Script Engine Demo ===");
console.log("Execution started at: " + new Date().toISOString());

// --- 1. Create a new issue ---
console.log("\n--- Step 1: Creating Issue ---");
var newIssue = jdc.issue.createIssue(
  projectId,           // from context
  issueTypeId || null,  // from context (or null for default)
  "SIL Demo: Auto-generated by Script Engine",
  {
    description: "This issue was created by the JDC Script Engine during a live demo.\n\nTimestamp: " + new Date().toISOString(),
    priorityId: null
  }
);
console.log("Created issue: " + JSON.stringify(newIssue, null, 2));

// --- 2. Add a comment to the current issue ---
console.log("\n--- Step 2: Adding Comment ---");
var comment = jdc.issue.addComment("Automated comment from JDC Script Engine demo - " + new Date().toISOString());
console.log("Comment added: " + JSON.stringify(comment));

// --- 3. Read issue data ---
console.log("\n--- Step 3: Reading Issue Data ---");
var currentIssue = jdc.issue.getCurrentIssue();
console.log("Current issue fields: " + JSON.stringify(currentIssue, null, 2));

// --- 4. JQL Search ---
console.log("\n--- Step 4: JQL Search ---");
var results = jdc.search.jql("ORDER BY created DESC", 5);
console.log("Found " + results.length + " issues via JQL");
for (var i = 0; i < Math.min(results.length, 3); i++) {
  console.log("  - " + (results[i].issueKey || results[i].id) + ": " + (results[i].summary || "No summary"));
}

// --- 5. Label Management ---
console.log("\n--- Step 5: Label Management ---");
jdc.issue.addLabel("demo-script");
jdc.issue.addLabel("automated");
var labels = jdc.issue.getLabels();
console.log("Labels after adding: " + JSON.stringify(labels));

// --- 6. Worklog ---
console.log("\n--- Step 6: Adding Worklog ---");
var worklog = jdc.issue.addWorklog("30m", "Script engine demo execution time");
console.log("Worklog added: " + JSON.stringify(worklog));

// --- 7. Persistent Variables ---
console.log("\n--- Step 7: Persistent Variables ---");
vars.set("demo-last-run", new Date().toISOString());
vars.set("demo-run-count", "1");
var lastRun = vars.get("demo-last-run");
console.log("Stored persistent var 'demo-last-run': " + lastRun);

// --- 8. File I/O (in-memory) ---
console.log("\n--- Step 8: In-Memory File I/O ---");
file.writeFile("demo-report.txt", "JDC Script Engine Demo Report\n");
file.appendToFile("demo-report.txt", "Generated: " + new Date().toISOString() + "\n");
file.appendToFile("demo-report.txt", "Issues found: " + results.length + "\n");
console.log("File content:\n" + file.readFile("demo-report.txt"));
console.log("File size: " + file.getFileSize("demo-report.txt") + " bytes");

// --- 9. Testing Framework ---
console.log("\n--- Step 9: Testing Framework ---");
test.assertTrue(typeof jdc === "object", "jdc API is available");
test.assertTrue(typeof console.log === "function", "console.log works");
test.assertNotNull(issueId, "issueId is in context");
test.assertEquals("object", typeof jdc.issue, "jdc.issue is accessible");
test.assertTrue(results.length >= 0, "JQL search returned results array");
console.log("Test results: " + test.getPassed() + " passed, " + test.getFailed() + " failed");

// --- 10. Error Tracking ---
console.log("\n--- Step 10: Error Tracking ---");
jdc.clearLastError();
jdc.issue.transitionIssue("non-existent-id", "fake-transition");
var lastErr = jdc.getLastError();
console.log("Last error after failed operation: " + (lastErr || "none"));

console.log("\n=== Demo Complete ===");
console.log("Total execution proves: issue CRUD, comments, JQL search,");
console.log("labels, worklogs, persistent vars, file I/O, testing, error tracking");

// Return value
({
  status: "success",
  issueCreated: newIssue.id || "created",
  jqlResults: results.length,
  testsPassed: test.getPassed(),
  testsFailed: test.getFailed()
});
```

### Step 3: Set the context

Replace the context JSON (right panel) with:

## Demo Scenario 2: DSL Transpiler — SIL-Like Syntax

**What it proves:** Scripts can be written in SIL-like syntax (`assignee = "john"`, `addComment("text")`) and the DSL transpiler automatically converts them to JavaScript before execution.

### Step 1: Use the Transpile Preview

Via cURL (or in the Console):

```bash
curl -s -X POST http://localhost:8080/api/workflow/scripts/transpile \
  -H "Content-Type: application/json" \
  -d '{
    "scriptBody": "// SIL-like syntax demo\nassignee = userId;\npriority = \"High\";\nsummary = \"Updated by DSL\";\naddComment(\"Field updated via DSL transpiler\");\nlogInfo(\"DSL execution complete\");\nvar issues = jqlSearch(\"project = DEMO\", 10);\nconsole.log(\"Found \" + issues.length + \" issues\");\ntrue;"
  }' | python -m json.tool
```

**Expected output:**
```json
{
  "original": "// SIL-like syntax demo\nassignee = userId;...",
  "transpiled": "// SIL-like syntax demo\njdc.issue.setFieldValue(\"assigneeId\", userId);...",
  "hasDslSyntax": true,
  "changed": true
}
```

### Step 2: Run the DSL Script in Console

Paste this in the Script Console:

```javascript
// ============================================================
// DEMO 2: DSL Transpiler — SIL-Like Syntax
// These lines use SIL-style syntax. The transpiler converts
// them to jdc.issue.setFieldValue() calls automatically.
// ============================================================

console.log("=== DSL Transpiler Demo ===\n");

// --- SIL-style field assignments (auto-transpiled) ---
console.log("Step 1: Setting fields via SIL syntax...");
summary = "Updated by JDC DSL Transpiler at " + new Date().toISOString();
description = "This field was set using SIL-like syntax: description = 'value'";
environment = "Production";
storyPoints = 8;
console.log("Fields set successfully via DSL syntax");

// --- SIL-style function calls (auto-transpiled) ---
console.log("\nStep 2: Calling functions via SIL aliases...");
addComment("Comment added via SIL alias: addComment()");
logInfo("This was logged via SIL alias: logInfo()");

// --- Verify the transpiler worked ---
console.log("\nStep 3: Verifying field values...");
var currentSummary = jdc.issue.getFieldValue("summary");
console.log("Summary after DSL set: " + currentSummary);

// --- Show what happened behind the scenes ---
console.log("\n=== What the DSL Transpiler Did ===");
console.log("summary = 'text'        -> jdc.issue.setFieldValue('summary', 'text')");
console.log("assignee = userId       -> jdc.issue.setFieldValue('assigneeId', userId)");
console.log("addComment('text')      -> jdc.issue.addComment('text')");
console.log("logInfo('msg')          -> jdc.log.info('msg')");
console.log("jqlSearch(q, n)         -> jdc.search.jql(q, n)");
console.log("httpGet(url)            -> http.get(url)");
console.log("setPersistentVar(k, v)  -> vars.set(k, v)");

console.log("\n=== DSL Demo Complete ===");
true;
```

**Expected output:** Console shows each SIL-style operation executing successfully, with a reference table of transpiler mappings at the end.

## Demo Scenario 3: Create a Persistent Script + Event Listener + Scheduled Job

**What it proves:** Full script lifecycle — create a script via API, attach it as an event listener, verify it fires on events, and show the execution log.

### Step 3a: Create a Condition Script

Go to the **Scripts** tab and click **Create Script**:

- **Name:** `Demo Condition — Block Close Without Comment`
- **Key:** `demo-block-close-no-comment`
- **Type:** CONDITION
- **Body:**
```javascript
// Condition: Only allow transition if a comment was provided
// Returns true (allow) or false (block)

console.log("Evaluating condition: comment required for transition");
console.log("Comment value: " + JSON.stringify(comment));
console.log("Screen input: " + JSON.stringify(screenInput));

var hasComment = false;

// Check direct comment from transition
if (comment && comment.trim().length > 0) {
  hasComment = true;
}

// Check screen input comment
if (screenInput && screenInput.comment && screenInput.comment.trim().length > 0) {
  hasComment = true;
}

if (!hasComment) {
  console.warn("BLOCKED: No comment provided for this transition");
}

console.log("Result: " + (hasComment ? "ALLOWED" : "BLOCKED"));
hasComment;
```

Click **Save**. The script is now stored in the database with version 1.

### Step 3b: Create a Validator Script

Click **Create Script** again:

- **Name:** `Demo Validator — Story Points Required for Stories`
- **Key:** `demo-story-points-required`
- **Type:** VALIDATOR
- **Body:**
```javascript
// Validator: Story Points must be set for Story type issues
// Returns null (valid) or error message string (invalid)

console.log("Validating: story points required for Stories");
console.log("Issue type: " + (issueData.issueTypeName || "unknown"));

var issueType = issueData.issueTypeName || "";
var storyPoints = issueData.storyPoints;

if (issueType === "Story" && (!storyPoints || storyPoints <= 0)) {
  console.warn("VALIDATION FAILED: Story Points required");
  "Story Points are required for Story type issues. Please estimate the effort.";
} else {
  console.log("VALIDATION PASSED");
  null; // null = valid
}
```

### Step 3c: Create a Post-Function Script

Click **Create Script** again:

- **Name:** `Demo Post-Function — Auto-Label + Comment on Transition`
- **Key:** `demo-auto-label-transition`
- **Type:** POST_FUNCTION
- **Body:**
```javascript
// Post-function: Add label + comment when issue transitions

console.log("=== Post-Function Executing ===");
console.log("Transition: " + transitionName);
console.log("From: " + fromStatusId + " -> To: " + toStatusId);

// Add transition label
var labelName = "transitioned-" + new Date().toISOString().split("T")[0];
jdc.issue.addLabel(labelName);
console.log("Added label: " + labelName);

// Add audit comment
var commentText = "Issue transitioned via '" + transitionName + "' at " +
  new Date().toISOString() + " by user " + userId;
jdc.issue.addComment(commentText);
console.log("Added audit comment");

// Store transition in persistent vars
vars.set("last-transition-" + issueId, JSON.stringify({
  transition: transitionName,
  from: fromStatusId,
  to: toStatusId,
  timestamp: new Date().toISOString(),
  user: userId
}));
console.log("Stored transition data in persistent vars");

// Log to server
jdc.log.info("Post-function complete for transition: " + transitionName);

console.log("=== Post-Function Complete ===");
true;
```

```bash

    "scriptType": "CONSOLE",
```

## Talking Points During Demo

1. **"No vendor lock-in"** — Uses standard JavaScript (ECMAScript 2022) instead of proprietary SIL syntax
2. **"But SIL users feel at home"** — DSL transpiler accepts `assignee = "john"` syntax automatically
3. **"232 API methods"** — More functions than SIL's 272 applicable functions (when including JS built-ins for string/math/date/array)
4. **"Enterprise-safe"** — Sandboxed execution, statement limits, timeouts, memory monitoring, email rate limiting
5. **"Full audit trail"** — Every execution logged with script key, mode, duration, success, API call count
6. **"Version control built-in"** — Every save creates a version, diff viewer, one-click revert
7. **"Zero deployment"** — Scripts are stored in the database, no JAR deploys, no server restarts
8. **"Monaco editor"** — Full IDE experience with 200+ API autocomplete items, syntax highlighting, Ctrl+S save
